Document the `Dumps` record properties. Each field of `EntityHit`, `DumpLineError`, `PageRef`, `Contributor`, `Revision`, `PageRevisionHit`, `PageRevisionError` and `XmlToken`, and of `tokenizeXml`'s result, now has a doc comment saying what it holds, when it is `null`, and how it is bounded. Line numbers count every line of the decompressed dump, framing and blank lines included. A `DumpLineError`'s `raw` is cut to 500 UTF-16 code units. The XML reader's short fields are trimmed and cut to 4,096 UTF-16 code units, numeric fields are `null` unless they are a non-negative decimal integer of at most 18 digits and no larger than `Number.MAX_SAFE_INTEGER`, and `Revision.text` is neither trimmed nor cut. Three existing comments are corrected. `DumpLineError` no longer says a bad line never fails the stream: a line with a malformed nested container can still end it as a defect (#147). `PageRevisionError` now lists every case that produces it, including a stray `</revision>`. The entities module comment and `EntityHit.item` no longer overclaim: #147 can end the stream, and only `Q`, `P` and `L` ids decode (a MediaInfo or EntitySchema line is `dumps/not-an-entity`). `Revision` no longer says its content is always wikitext. Two current limitations are documented rather than fixed: a multi-slot revision's `model`, `format` and `text` come from its last slot, not the main one (#154), and the 16,777,216 cap that the `detail` message calls bytes counts UTF-16 code units (#155). Nothing else changes.
