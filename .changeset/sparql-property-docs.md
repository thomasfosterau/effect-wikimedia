Document every `Sparql` property. Each field of `UriTerm`, `LiteralTerm`, `BlankNodeTerm` and `UnknownTerm`, and of the lenient `SparqlResultsResponse` schema, now has a doc comment saying what it holds, when it is `null` or `""`, and how it is bounded: a term's `value` is cut at 10,000 UTF-16 code units, a literal's `datatype` at 2,000 and its `language` at 40, and none is trimmed or validated. `LiteralTerm.value` is the lexical form, never parsed into a number or a date. `SparqlResultsResponse` stays in the docs, because the exported `normaliseResults` takes it; its comment now says which malformed responses fail the decode (reported as `RequestFailed`) and points to the typed `SparqlResults`. `SparqlResults.vars` now says that entries that are not strings are dropped and each is cut at 200 UTF-16 code units. Two existing comments are corrected: `LiteralKind` and `literalKind` now say that `xsd:date`, like `xsd:dateTime`, maps to `"time"`. Two current limitations are documented rather than fixed: an `ASK` query's `boolean` answer is not read, so `query` returns empty `vars` and `bindings` for it (#149), and `UnknownTerm.type` is not length-capped (#150). Nothing else changes; the comments on the schema fields also appear in the built JavaScript.
